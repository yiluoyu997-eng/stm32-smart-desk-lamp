# 功能需求

## 1. 项目目标

台灯根据人员是否在桌前和桌面实际照度决定是否补光，并允许用户随时切换到手动控制。控制应当平滑、稳定，传感器短时波动或通信异常不能造成灯光突然反复亮灭。

## 2. 当前软件测试参数

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| 最低有效亮度 `Bmin` | 10% | 非零亮度不得低于此值 |
| 暗阈值 | 250 lux | 从明亮状态重新判定为暗 |
| 亮阈值 | 350 lux | 从暗状态判定为明亮 |
| 无人待机亮度 | 10% | 人员刚离开后的过渡亮度 |
| 无人延时 | 120 s | 有效无人持续时间达到后关灯 |
| 渐变速度 | 20%/s | 电脑模拟器中的亮度变化速度 |
| 雷达恢复确认 | 3帧 | 故障后连续有效帧数量 |
| 闹钟呼吸周期 | 2 s | 灯光提醒的一个呼吸周期 |
| 闹钟超时 | 60 s | 无人操作时自动停止提醒 |

这些数值用于验证控制逻辑，不是最终产品标定值。实物阶段必须根据灯具功率、安装距离、桌面反射和BH1750位置重新测量。

## 3. 自动模式

1. 软件电源关闭时，目标亮度为0。
2. 软件电源打开且环境明亮时，无论是否有人，灯保持关闭。
3. 环境较暗且检测到有人时，根据照度区间给出目标亮度并平滑变化。
4. 暗环境下从有人变为无人时，先降到10%待机亮度。
5. 有效无人累计120秒后，目标亮度降到0。
6. 延时期间人员返回，应立即取消关灯流程并重新计算目标亮度。
7. 250/350 lux迟滞区间用于防止临界点附近反复开关。

## 4. 手动模式

1. 用户设置亮度或色温时切换到手动模式。
2. 亮度为0表示用户主动关灯；非零亮度不得低于10%。
3. 手动模式下，照度和人员状态不修改用户亮度。
4. 用户切回自动模式后，立即根据最新传感器状态重新决策。

手机、语音、旋钮和按键最终都转换为统一命令，由STM32控制器处理，不能各自直接写PWM。

## 5. 故障处理

- BH1750数据无效：冻结进入故障前的实际亮度；有效数据恢复后重新自动计算。
- LD2410数据无效：人员状态记为未知，冻结无人计时，避免误关灯。
- LD2410通信恢复：连续3帧有效数据后才恢复自动人员控制；任一无效帧会重新计数。
- 两个传感器同时异常：仍允许手动控制和软件关机。

仅凭传感器持续报告“无人”无法区分真的无人和传感器内部错误。实物阶段还需要结合UART通信超时、数据帧校验、模块心跳或自检信息判断通信健康度。

## 6. 闹钟提醒

- 支持单次闹钟和每日闹钟；
- 用户可设置软件关灯时是否允许闹钟触发；
- 触发时使用灯光呼吸变化提醒，不承诺声音提醒；
- 任意实体按键可停止闹钟，但本次按键不执行原有控制功能；
- 停止或超时后恢复闹钟前的软件电源和模式，再重新检查自动模式环境。
